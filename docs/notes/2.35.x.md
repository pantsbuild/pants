#### JVM

The default version of Coursier is now [`v2.1.27`](https://github.com/coursier/coursier/releases/tag/v2.1.27) (previously `v2.1.24`). This fixes a bug where a transitive dependency could be left out of the dependencies of a lockfile entry ([#22909](https://github.com/pantsbuild/pants/issues/22909)). Setting `[coursier].version = "v2.1.24"` restores the previous version, and a lockfile generated with either version works with the other. Changes to be aware of:

- The Linux binaries require glibc 2.34 or newer, and the macOS binaries are built for macOS 15 or newer.
- The Linux ARM binary now comes from the main Coursier releases, so it is downloaded through `[coursier].url_template` (as `cs-aarch64-pc-linux.gz`) if you point that at a mirror.
- Regenerating a JVM lockfile may change some `file_name`s (which lose a `_jar_` segment), remove duplicate entries and add dependencies that were previously missing.
- Coursier's new JVM index no longer writes versions with a legacy `1.` prefix, so Pants now passes a JDK such as `temurin:1.11` to Coursier as `temurin:11`, and the defaults of `[jvm].jdk` and `[jvm].tool_jdk` are now written as `temurin:11`. With a custom `[coursier].jvm_index`, the JDK is tried as written first. Existing settings keep working, with two exceptions: version ranges such as `temurin:[1.11,1.17)` are not rewritten, and a bare version such as `17` may resolve to a different vendor (write `temurin:17` to pin it).
- Pants now sets `COURSIER_MAVEN_SETTINGS=false` when running Coursier, so that mirrors in a Maven `settings.xml` still do not redirect the repositories in `[coursier].repos`, as they otherwise would from Coursier `v2.1.25`.

Fixed the JDK chosen for Scala BSP workspaces when targets mix JDKs written with and without the legacy `1.` prefix.

#### Python

The built-in default tool lockfiles were switched from `pex` to `uv` format. This should have no
functional impact, but if you notice a bug that you think is related, please [report it](https://github.com/pantsbuild/pants/issues).

When using `uv` lockfiles, you can set a new `[python].create_venv_repository_from_entire_lockfile`
option. This affects how Pants builds the intermediate, internal-only venvs that pex uses as
wheel repositories. If true (the default) the entire lockfile will be materialized into the venv,
resulting in creation of fewer, larger venvs. If false, only the requirements actually needed
by the pex will be used, resulting in creation of more, smaller venvs. This may be useful if
you have a lockfile with massive requirements that are not always needed. Note that when first
setting this option to False you may need to regenerate the lockfile to ensure that it contains
enough information to create the subset venv.

`generate-lockfiles` (without `--sync`) now overwrites an existing `uv` lockfile that fails to parse, rather than failing with a `TOMLDecodeError`.

Upgraded the default `docformatter` version to 1.7.8, so that Python 3.13 and 3.14 are supported.

Upgraded the default `coverage-py` version to 7.14.3.
