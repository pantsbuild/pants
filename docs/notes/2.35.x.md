## What's New

### Highlights

- The default version of Coursier, which the JVM backends use to resolve dependencies and to provision JDKs, is now [`v2.1.27`](https://github.com/coursier/coursier/releases/tag/v2.1.27). Its Linux binaries require glibc 2.34 or newer, and its macOS binaries are built for macOS 15 or newer and may not run on older versions. This affects JVM users on older systems that Pants itself supports, such as RHEL 8, Debian 11 and Ubuntu 20.04. Setting `[coursier].version = "v2.1.24"` restores the previous version, which continues to work with this release. See the JVM section below for details.

#### JVM

The default version of Coursier is now [`v2.1.27`](https://github.com/coursier/coursier/releases/tag/v2.1.27) (previously `v2.1.24`). This fixes a bug where a transitive dependency could be left out of the dependencies of a lockfile entry ([#22909](https://github.com/pantsbuild/pants/issues/22909)). Things to be aware of:

- The Linux binaries require glibc 2.34 or newer, and the macOS binaries are built for macOS 15 or newer. If Coursier does not run on your system, set `[coursier].version = "v2.1.24"` to keep using the previous version.
- ARM binaries now come from the main Coursier releases, not from `VirtusLab/coursier-m1`. If you point `[coursier].url_template` at an internal mirror, the Linux ARM binary (`cs-aarch64-pc-linux.gz`) is now downloaded through it. As for `v2.1.24`, the macOS ARM binary is downloaded from github.com, through the URL in its `[coursier].known_versions` entry and not through `url_template`: to mirror it, override that entry.
- If you override `[coursier].known_versions`, add entries for `v2.1.27` or set `[coursier].version` to a version you list.
- Regenerating a JVM lockfile may change some `file_name`s (which lose a `_jar_` segment), remove duplicate entries and add dependencies that were previously missing. Existing lockfiles continue to work, and a lockfile generated with `v2.1.24` or `v2.1.27` works with the other.
- Coursier now retries downloads that fail with a network or server error more often, so a repository that keeps failing takes longer to report it. Missing artifacts are not retried.
- JVM compiles, tests and other JVM processes miss the cache once after upgrading.

Coursier `v2.1.27` uses a new JVM index, in which versions are no longer written with a legacy `1.` prefix: a JDK such as `temurin:1.11` is not found in it. Pants now drops that prefix before calling Coursier, so that `temurin:1.11` is passed as `temurin:11`. A JDK whose version starts with `1.`, whether in `[jvm].jdk`, `[jvm].tool_jdk` or the `jdk` field, therefore keeps working, with both `v2.1.24` and `v2.1.27`. The defaults of `[jvm].jdk` and `[jvm].tool_jdk` are now written as `temurin:11`, which is the same JDK as before. Three cases need attention:

- A JDK given as a bare version, such as `jdk = "17"`, may now resolve to a different vendor (on macOS ARM, `17` now resolves to Zulu, not Temurin). Name the vendor (`temurin:17`) to pin it.
- Version ranges written with the prefix, such as `temurin:[1.11,1.17)`, are not rewritten, so they may not match the new index.
- A custom `[coursier].jvm_index` that writes some versions of a JDK with the `1.` prefix and others without (`1.8` next to `17`) no longer matches the prefixed ones. Write that JDK's versions consistently, all with or all without the prefix.

Pants now sets `COURSIER_MAVEN_SETTINGS=false` when running Coursier. Since `v2.1.25`, Coursier otherwise applies the mirrors of the user's Maven `settings.xml` on top of the repositories it is given. This keeps the behaviour of `v2.1.24`: mirrors in `settings.xml` do not redirect the repositories in `[coursier].repos`.

Fixed the JDK chosen for Scala BSP workspaces when targets mix JDKs written with and without the legacy `1.` prefix: `temurin:1.17` was treated as older than `temurin:11`.

#### Python

The built-in default tool lockfiles were switched from `pex` to `uv` format. This should have no
functional impact, but if you notice a bug that you think is related, please [report it](https://github.com/pantsbuild/pants/issues).

`generate-lockfiles` (without `--sync`) now overwrites an existing `uv` lockfile that fails to parse, rather than failing with a `TOMLDecodeError`.

Upgraded the default `docformatter` version to 1.7.8, so that Python 3.13 and 3.14 are supported.

Upgraded the default `coverage-py` version to 7.14.3.
